# Component and Dependency Architecture

## Application composition

`app/composition/container.py` exposes the assembled services. The builder and
submodules wire repositories first, then capability services, then runtime and
interface-facing boundaries. The FastAPI application imports the composition
container only after settings and application startup are valid.

```text
interfaces/admin  -> capabilities -> infrastructure/database
       |                  |                  |
interfaces/mcp    -> capabilities -> infrastructure/ssh / llm/ollama
       |                  |
runtime/claude     -> interfaces/mcp + bounded runtime contracts

core contracts/policies are shared by all paths; no interface owns policy.
```

## Capability map

- `app/capabilities/monitoring`: server, profiles, commands, scheduler, report
  collection and report query.
- `app/capabilities/analysis`: report normalization, fingerprints, retrieval,
  Ollama analysis orchestration, and analysis persistence.
- `app/capabilities/knowledge`: source registry, ingestion, parsing, chunking,
  indexing, and hybrid retrieval.
- `app/capabilities/investigation`: routing, Specialist registry/definitions,
  context, execution, Evidence collection, correlation, final diagnosis, and
  persisted read models.
- `app/capabilities/remediation`: plans, sandbox validation, approvals,
  named execution, verification, rollback, autonomous policy/history,
  authorization, reservation, and circuit-breaker services.

## Interface map

The Web and API route inventory is generated by `tools/dev/list_routes.py`.
The current verified inventory is 99 routes: 73 OpenAPI routes and 26
web-only routes. The API permission mapper is in `app/interfaces/admin/auth.py`;
the backend remains authoritative even when UI controls are hidden for a role.

The MCP catalog is grouped into monitoring, reports, retrieval, investigation,
Specialists, and remediation. The public count is 25; all tools have typed
schemas and bounded handlers.
